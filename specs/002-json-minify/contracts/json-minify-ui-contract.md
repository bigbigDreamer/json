# UI Contract: JSON 一键压缩

## Goal

定义 Aura JSON Studio 中“一键压缩”交互的稳定用户契约，确保设计、实现和测试对齐。

## Entry Points

- 输入区工具栏新增一个明确可见的压缩触发操作
- 该操作与现有“格式化 JSON”并存，二者都基于当前输入执行
- 键盘快捷操作若扩展到压缩，必须保持与当前主流程一致且不会误触覆盖已有行为

## Preconditions

- 用户已在输入区提供待处理文本
- 系统会先执行既有的隐形字符清理，再尝试解析 JSON
- 若解析失败，压缩流程立即终止

## Success Contract

- 成功后，界面必须明确显示当前结果是“压缩结果”而不是“格式化结果”
- 用户必须能通过一次复制动作拿到完整压缩 JSON
- 原始输入内容不得被自动覆盖
- 现有结构树浏览能力不得因压缩功能而消失或退化
- 若输入原本已经是压缩 JSON，系统仍返回成功结果，并保持结果稳定

## Error Contract

- 非法 JSON 输入时不得展示新的压缩结果
- 错误提示必须是可理解的用户语言，而不是仅暴露底层异常上下文
- 若系统已自动清理隐形字符但仍解析失败，反馈中必须说明清理已发生

## Copy Contract

- 复制结果必须与界面展示的压缩文本完全一致
- 复制成功和失败都要有即时反馈
- 现有“复制全部 / 复制节点 / 复制值”行为不得被破坏

## Acceptance Mapping

- 对应 `spec.md` 中 User Story 1: 一键生成压缩结果
- 对应 `spec.md` 中 User Story 2: 快速复制压缩结果
- 对应 `spec.md` 中 User Story 3: 无效输入时获得明确反馈
